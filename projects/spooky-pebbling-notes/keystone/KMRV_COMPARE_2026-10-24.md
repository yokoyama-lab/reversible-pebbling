# KMRV の逐次 pebbling cost の厳密値（2026-10-24）

KMRV（Kahanamoku-Meyer・Ragavan・Van Kirk，arXiv:2510.08432v3，EUROCRYPT 2026）の鎖のゲーム（Def 2.1–2.8．抜き書きは `KMRV_TABLES_2026-10-24.md`）:
頂点 1..ℓ（0 は常にペブルのダミー），始状態＝終状態＝全部空，途中で ℓ にペブルを置く，Pebble(i) は i−1 がペブルで i が空かゴースト，Unpebble(i) は i−1・i がペブル，Ghost は前提なし，
cost = #Pebble + #Unpebble（Ghost は 0），空間 s = 同時のペブル数（ゴーストは数えない）。彼らは **逐次の cost の厳密値を一つも与えていない**（2.4 節で「総操作数の最小化」を望ましい指標と書くだけ）。

## 結果

**W*_KMRV(ℓ, s) = T_UG(ℓ, s)/2 + ℓ = (T_UP(ℓ, s) + δ(ℓ, s))/2 + ℓ**，
T_UP(ℓ,s) = max_m (2mℓ − β_m(s))（Envelope.lean），δ = +1（ℓ < θ(s) = s(s+1)/2）／ −1（ℓ ≥ θ(s)）（Keystone.lean）。KSS の T_P(ℓ+1,s+1) = T_UG(ℓ,s) + 1 を使えば W* = (T_P(ℓ+1,s+1) − 1)/2 + ℓ。

### 紙の証明（層 2。Lean 化は未実施だが Work.lean/SpookyDag と同じ道具で書ける）

1. **W = T_round/2 + ℓ の等式**（`SpookyDag/Work.lean` の議論の「終端も空に戻す」版）。全手数を T_round（Ghost も 1 手）とする。始状態も終状態も空なので #Pebble = #Unpebble + #Ghost，T_round = 2·#Pebble。
   各頂点は一度は置かれ（ℓ に置くには ℓ−1 が要る，帰納），終状態に幽霊が無いので各頂点の最後の手は Unpebble。よって #Unpebble ≥ ℓ，W = #Pebble + #Unpebble ≥ T_round/2 + ℓ。
   逆に，最後でない Unpebble を Ghost に，その頂点への次の Pebble を（ゴースト上の）Pebble に読み替えても前提（ペブルの位置だけを見る）は保たれ，手数と空間は変わらず #Unpebble = ℓ。ゆえに W* = T*_round/2 + ℓ。
2. **T*_round(ℓ,s) = T_UG(ℓ,s)**。（≤）T_UG の最適手順は G={ℓ} から始まり，ℓ への最初の手は unghost(ℓ)。ゴーストは他の手の前提に関わらないので，同じ手順を空の盤から打ち unghost(ℓ) を pebble(ℓ) に替えれば合法で，ℓ を置いて空に戻る。
   （≥）round trip で ℓ に最初に置く手より前には ℓ への手は無い（空の頂点には pebble しか打てない）。同じ手順を G={ℓ} から打ち，その pebble(ℓ) を unghost(ℓ) に替えれば合法で，空に戻る。
3. したがって W*_KMRV = T_UG/2 + ℓ。T_UG は偶数（T_UP は奇数，δ は奇数）。

### 検算（`kmrv/`）

## 追補 2026-10-28: touch-and-go と重みつき空間（`kmrv/kmrv_weighted.py`，`kmrv/kmrv_weighted_table.py`）

### 訂正: 「W* は Per run の下界」は「W* − 1 が下界」
表 5・6 の Depth が 2ℓ−1 になる行があることから，4 節の最適化は touch-and-go（終端は置いた直後に測定して消え，Unpebble(ℓ) は打たない．4.1 節 項目 2）と読める【推測，前節の検算メモと同じ】．
touch-and-go の最小 cost を W*_tng と書くと **W*_tng = W* − 1**（21 行すべて．下の構成と全数探索）．
- 下界（紙）: touch-and-go の手順に，Pebble(ℓ) の直後に Unpebble(ℓ) を 1 手足すと往復の手順になる（ℓ−1 はその時点でペブル，空間は Pebble(ℓ) の手と同じ）．よって W* ≤ W*_tng + 1．重みつきでも同じ．
- 上界: 往復の構成の基底（置いて外す 2 手）を「置いて測定」1 手に替えた構成（replay で検査）．
- 比 Per run / W*_tng は 1.12〜1.24 のまま（前節の表の W* から 1 引くだけ）．

### 重みつき空間（付録 B 末尾）
論文は「i ≡ 1 (mod w+1) の Pebble(i)・Unpebble(i) は一時値 t の空間が要る」と書くが**重みの大きさ（t が何 n 量子ビットか）を数で書いていない**．
そこで t をペブル c 個ぶん（c = 0, 1, 2）とおき，空間 = Def 2.8 の s_t ＋ その手の重み，で最小 cost を求めた．
- 構成: Lean の分解（`decomp_ug_le`: TUG(n,s) ≤ 2k−1+TUP(k,s)+TUG(n−k,s−1)，`decomp_le`，Cap2 の「終端を先にゴースト」）を区間の大域位置つきにした DP．手順を出して別実装の replay で合法性・空間・手数を検査．
- c=0・往復では Lean の閉じた形（`kmrv_formula.tug`）と 2≤n<60・2≤s≤8 で全一致．
- 全数探索との照合: c∈{0,1,2}×{往復, touch-and-go}×L≤14×s≤7 の 564 組で不一致 0（L≤10 は s=1..7，L=11..14 は s=2..7）．**L≥15 で DP が最適かは未証明**（重みつきの分解定理は無い）．よって重みつきの値は**上界（構成）**で，下界は重み無しの W*_tng．

- **c=1 なら**，彼らの深さ最適解の乗算数は，同じ重みつき空間での逐次の最小（の構成値）の 1.10〜1.22 倍．逐次に直せば乗算数を 9〜18% 減らせる（深さは増える）．
- **c の推定は決まらない**: KMRV Remark 4.3「s=4 より小さい s では解が無い」「s=4 の解は数千」．c=1 だと s=3 でも解がある（ℓ=79 で 1259）ので合わない．c=2 だと s=3 は解なし・s=4 は 1209〜2100（数千）で合うが，s=5 の構成値 545（ℓ=88）が Per run 500 を上回る．DP が ℓ=88 でも最適なら c=2 は表と矛盾する（DP の最適性は L≤14 でしか確かめていない）．彼らの s が「Def 2.8 の s − 1」（コードの max_pebbles = s−1）なら，重み無しでも W*_tng(79,4) = 456 > 429 で表と矛盾する．**重みの定義は著者のコードか問い合わせでしか確定しない**（公開コード v0.1 には重みつき最適化が入っていない）．
- 層: W*_tng = W* − 1 は紙の証明（上界は構成＋replay，下界は 1 手足す議論）．重みつきの値は構成（上界）と小さい ℓ の全数一致（層 3）．
