## 方法: 自己同型の商の上のフロンティア BFS

SAT（2788 手 × 255 頂点）は UNSAT の証明が現実的でないので採らず、状態空間を全部掃いた。
T_8 で 11 個以下の盤の軌道は高々 52,497,674,884（`orbcount.py`）で、全状態を覚える BFS には載らない。
そこで 3 層だけ持つ BFS にした。

### 正しさの根拠
1. **無向**: v を置く手が合法なら v を外して戻る手も合法（合法性は v の子だけで決まる）。
2. **二部**: 1 手でペブル数が ±1。深さ d の盤のペブル数の偶奇は d と一致（A・B とも全状態で実行時に検査）。
3. よって **L_{d+1} = N(L_d) \ L_{d−1}**。前・今・次の 3 層で層が正確に決まる。
4. **商**: Aut(T_H) は合法性とペブル数を保つ。軌道の道は帰納的に持ち上がる（[x_i]〜[x_{i+1}] の代表 x', x'' と
   σ(x')=y_i なる σ をとれば σ(x'') は y_i の隣）。ゴールの軌道は {根} だけなので、商の距離 = 元の距離。
5. ゴールが層 d に初めて現れれば M = d。層が空になれば到達不能。打ち切りは「未確定」。

### 2 つの独立な実装
| | A（`fbfs.c`） | B（`fbfs_b.c`） |
|---|---|---|
| 表現 | 高さ H−2 の部分木の軌道に番号（(b,L,R)、L≤R の hash-cons）、上 2 段を明示して 128 ビット | 再帰配置のビット列。正準形 = 各節点で左 block ≤ 右 block（辞書式）。鍵はペブル位置の昇順列 |
| 後継 | 高さ H−2 の後継表を ∅ からの閉包で前計算 | 盤の上で合法性を直接調べ toggle、祖先を辿って左右を入れ替え直す |
| 間引き | A=B なら B の手、半分が等しければ半分 2 の手を省く | 等しい兄弟の右側には降りない（空の部分木は最左の葉だけ）。打つ直前に合法性を再検査 |

**対称性の間引きの健全性**（依頼 3）: 節点 a の左右の block が等しいとき、a での入れ替え σ は盤を保つ自己同型で、
右の block の v を左の σ(v) に移す。v と σ(v) の toggle の結果は σ で移り合う（同じ軌道）。複数の祖先が該当しても、
最も上の該当祖先での入れ替えを繰り返せば代表に移る。実測でも B の枝刈りあり・なし（`--noprune`）・素朴版
`fbfs_b_naive.c` の三者が h≤6 の全 12 組で A と層ごとに一致。

## 変異注入（`python3 mutate.py <リポ外の作業場所>` → `logs/mutation.log`、約 3 分）
リポジトリ外のコピーを 1 か所ずつ書き換え、無変異の対照（既知の 10 点を再現）と**組ごとにその場で**比べた。
判定は「M が既知と違う／層ごとの状態数が対照と違う／異常終了（不変条件の検査で停止を含む）」のどれかで検出とし、
時間切れの組は、打ち切った時点までに書かれた層が対照と食い違っていれば検出、食い違いが無ければ「未判定」とする
（検算者の指摘 4 で、時間切れをそのまま検出に数えるのをやめた）。
- A: **10/10 検出**（合法性・上限・対称性の省略・正準化・前層の除外・ペブル数の計算）。A6・A9（正準化を崩す変異）は
  M を変えず、層ごとの状態数で検出された。
- B: **14/15 検出**。B13（鍵の比較を先頭 8 バイトだけにする）は h=6 p=9 で時間切れになったが、それまでの層が
  深さ 69 で対照と食い違っていた（31,845 対 31,844）。未検出の B15 は「打つ直前の合法性の再検査」を緩めたもので、
  候補の列挙と重複する保険なので単独では検出されないのが正しい（事前に等価変異として分類）。
- 検査器 check_seq.py: **4/4 検出**（子の条件「だけ」を破る手順を含む合法 2・不合法 6 の試験）。
- 集合ハッシュの変換（A 側）を 4 通り壊す試験は別に行い、すべて B との食い違いとして検出（上の結論）。

## 独立の検算（検算者エージェント、2026-10-16）
前工程の推論を見せずに主張と成果物の場所だけを渡した。判定は**主張 1〜4（M(T_8,11)=2789・論法・校正と変異注入の記述・状態数の上界）すべて一致**。
検算者は自前の第 3 の実装（3 層の前提を使わない全集合 BFS、別の正準形、商をとらない版も含む）で h≤7 の層を A・B と一致させ、
証人を自前の再生器で合法と確かめ、層ファイルを再集計した。指摘 4 件への対応:
1. p_min(T_8)=11 を BFS で確かめていない → T_8・S=10 を 2 実装で全探索して到達不能を確認（上の結論）。
2. 「全 3177 層」「最後の層は深さ 3176」は空の層を含む言い方 → 「3177 行、状態がある最後の層は 3175」に直した。
3. 原稿 l.180 の「深さ 2788 まで…（442 億状態）」は累計と全体が混ざる → `MANUSCRIPT_PATCH.md` の P1 で区別する案を出した。
4. 変異注入で時間切れを検出に数えるのは甘い → `mutate.py` を、各組を対照と即座に比べ、時間切れだけのものは「未判定」とする形に直した。
加えて「op の走行が深さ 238 まで一致」は証跡が無いとの指摘があり、実際に比べたのは深さ 140 までだったので訂正した。

## 再現
```
cd p5/h8
gcc -O3 -march=native -fopenmp -o fbfs fbfs.c         # 集合ハッシュ付きの最終版。sha256 は logs/digest/binaries.sha256
gcc -O3 -march=native -fopenmp -o fbfs_b fbfs_b.c
systemd-run --user --scope -p MemoryMax=24G -p MemorySwapMax=0 ./fbfs 8 11 --threads 12 --stop-at-goal 0 --layers lA.txt --digest dA.txt
systemd-run --user --scope -p MemoryMax=20G -p MemorySwapMax=0 ./fbfs_b 8 11 --threads 12 --stop-at-goal 0 --layers lB.txt --digest dB.txt
python3 compare_layers.py lA.txt lB.txt --goal 2789 && cmp dA.txt dB.txt   # 層の状態数と集合ハッシュ
./fbfs 8 10 --threads 8 --stop-at-goal 0 --layers lA10.txt --digest dA10.txt   # p_min(T_8)=11（到達不能）
python3 witness.py 8 11 > w.txt && python3 check_seq.py 8 11 w.txt
bash calibrate.sh 4; python3 mutate.py <リポ外の作業場所>
```

`logs/layers_h8_p11.txt`・`logs/layers_h8_p11_B.txt`。集合ハッシュ付きの版で回し直した A の層ファイルはこれと同一。
環境: <host> = Xeon Silver 4509Y・gcc 15.2.0（Ubuntu 15.2.0-4ubuntu4）、op = i7-13700・gcc 15.2.0（16ubuntu1）、
s3 = Broadwell・gcc 13.3.0。Python 3.15.0。ソルバ・検査器（SAT/DRAT）は使っていない。
