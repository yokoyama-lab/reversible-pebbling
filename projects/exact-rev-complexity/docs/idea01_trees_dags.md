# 候補1 — 可逆ペブリングの木・DAG 族への厳密拡張

> 一行: **Královič が「空間 $h+\Theta(\lg^* h)$」までしか決めなかった木族の、手数の厳密表を作る。**
> 期待値: 新規性 中／成功確率 **高**／既存資産の再利用 **最大**（本命）

## 1. 厳密量の定義

対象は DAG 族 $\{G_h\}$（完全二分木 $T_h$、spinal tree、バタフライ、ピラミッド）。
`docs/20_prior_art.md` §1 のモデルで

- $p_{\min}(G_h)$ = clean に根（終端）へ到達できる最小ピーク
- $M^*(G_h, p)$ = ピーク $p$ の下での最小手数、および $M^*(G_h) := M^*(G_h, p_{\min})$
- トレードオフ曲線 $p \mapsto M^*(G_h,p)$（$p = p_{\min} .. p_{\min}+3$）

## 2. 既知と空白

- **既知**: Královič は完全二分木の可逆ペブル**空間**が $h+\Theta(\lg^* h)$ であることを示した
  （標準ペブリングは $h+1$。可逆化の超過分が $\lg^*$ という繊細な結果）。バタフライの空間も与えた。
- **空白**: **手数の厳密値がどこにも表化されていない。** さらに $\lg^*$ の段差が
  実際にどの $h$ で発生するか（onset）は未報告。$\lg^* h$ は極端に遅く増えるので、
  「理論上は増える」と「小さい $h$ で観測できる」の間に大きな隙間がある。
- **副産物**: de Rezende–Meir–Nordström–Robere (CCC 2019) の対応により、
  厳密 $(t,s)$ は **Nullstellensatz 反駁のサイズ $t+1$・次数 $s$ の厳密値**に直訳される。
  「木族の NS 反駁の厳密最小サイズ表」という証明複雑性側の主張が無料で付く。**ここを必ず書く。**

## 3. 機械化の設計（2026-07-27 改訂。実測に基づく）

`scripts/revpebble.py` が既に DAG 一般なので、**入力グラフを渡すだけ**で走る。
`complete_binary_tree(h)`, `pyramid(h)` は実装済み。
spinal tree・バタフライは `scripts/exp01b_engine.py` に追加した。

### 3.1 状態数の見積りが誤っていた（訂正）

> ~~状態空間は $2^{|V|}$ なので素朴 BFS は $|V|\le24$ 程度が限界~~

**これは過小評価だった。** ピーク上限 $p$ で切れば状態数は $\sum_{k\le p}\binom{n}{k}$ に収まり、
$p$ は $\log$ オーダーなので劇的に小さい（`pyr(5)*` は $|V|=21$ だが $p=8$ では 2.3 万状態）。
**この見直しだけで DP を書く前に $h$ が 2 つ伸びた。** 実際に到達した範囲:

| 手段 | 実装 | 到達範囲 |
|---|---|---|
| 素朴 BFS（frozenset） | `revpebble.bfs` | pyr $h\le6$（$p=10$ で 443 秒） |
| ビットマスク＋双方向 BFS | `exp01b_engine.py` | pyr $h\le6$（12.5 秒）、$T_h$ $h\le5$ |
| Aut 商グラフ BFS | `treedp.py` | $T_h$ $h\le6$（+ $p_{\min}$ は $h=7$） |

### 3.2 「フロンティア DP」「木 DP」は設計が誤っている（訂正）

> ~~木分解による分割統治: 部分木のインターフェース状態だけを持つ DP~~
> ~~ピラミッドは対角線断面が細いのでフロンティア DP が効く~~

**どちらも成り立たない。** 詳細は `data/exp01_results.md` §6-3,4。要点:

- 可逆ペブリングの手順は DAG の切断に沿って**単調に進まない**（置き／取りが任意に交錯し、
  切断の両側を何度も往復する）。「断面が細い」は**標準ペブリングの直観の誤った持ち込み**。
- 部分木 $A,B$ を結合しているのは**占有数の時間プロファイル**であり、
  $A$ を途中の低占有状態で待たせて $B$ を進める手順が実際に最適になる
  （Královič の $\lg^*$ 構成がまさにこれ）。有限インターフェースに潰すと最適解を落とす。
- 素朴に逐次化する DP は**上界しか与えない**。その上界は
  $p_{\min}(T_h)\le p_{\min}(T_{h-1})+2$ に対応し、実測の増分 $2,2,1,1,1,2$ に対して
  $h=4,5,6$ で真に最適でない。

### 3.3 効いた手（採用）

1. **ビットマスク＋双方向 BFS**（`exp01b_engine.py`）。トグル規則が対合＝状態グラフが**無向**
   なので双方向 BFS が合法。素朴比 20〜50 倍速。複数終端（マスク）にも一般化した。
2. **Aut 商グラフ探索**（`treedp.py`）。完全二分木の兄弟入れ替えで状態を割る。
   $\varnothing$ と目標 $\{\text{root}\}$ がどちらも Aut 不変なので
   **商上の最短距離は元の最短距離に厳密に等しい**（近似ではない）。
   軌道数の削減率は高さ5で 4500 倍、高さ6で 10 万倍。`exp01b_engine` 比でさらに 150 倍速。
3. **逐次合成を「$p_{\min}$ の上界証書」として使う**（`exp01b_certificate.py`）。
   最適 DP としては失敗だが、構成した手順を検証器に通せば上界の証明になる。
   これで $p_{\min}(T_7)=10$ を（下界＝全数探索、上界＝証書で）厳密に決めた。

**二重実装で照合**: `revpebble.bfs` ⟷ `exp01b_engine` ⟷ `treedp` を、重なる範囲の
**全 $p$**（到達不能の判定も含む）で一致確認済み。`tests/test_exp01b.py` と
`tests/test_exp01c_treedp.py`（計 30 件）。

## 4. 初日の実験（そのまま実行可）

```bash
cd ~/dev/github.com/tetsuo-jp/exact-rev-complexity
python3 tests/test_revpebble.py      # まず回帰テストが通ることを確認
python3 scripts/exp01_trees.py       # 木族の p_min・M*・トレードオフを data/ に出力
```

**初回実行はすでに済んでいる → 結果と読み取りは [`data/exp01_findings.md`](../data/exp01_findings.md)。**
要点だけ:

- 完全二分木（葉もペブル対象の流儀）: $(h, p_{\min}, M^*) = (1,3,5), (2,5,17), (3,6,53)$。
  $p_{\min}-h = 2,3,3$ で **$h=1\to2$ に段差が1つある**。$\lg^*$ 起源かの判定が主タスク。
  弱い予想（3点のみ）: $M^*(T_h) = 2\cdot3^h - 1$。$h\ge4$ は素朴 BFS では届かず**木 DP が必要**。
- ピラミッド: $M^* = 5, 13, 27, 47, 105$（$h=1..5$）。
  $h\le4$ は $3h^2-h+3$ に完全に当てはまるが $h=5$ で**当てはめが崩れた**（予測 73 / 実測 105）。
  → 跳ねの原因は $p_{\min}$ ではなく最適スケジュールの構造変化。**ここが面白い。**
- **正規化の問題は解消**: `cbt(h) all-pebbled` = `cbt(h+1) free-leaves` が厳密に一致した
  （$p_{\min}$・$M^*$ とも）。「葉を free にする」＝「1 レベル低い木を全ペブル」。
  文献と比較するときはレベルのずれ 1 だけ注意すればよい。

## 5. 成功判定と撤退条件

- **成功（最小ライン）**: $T_h$ の $M^*$ を $h\le6$ まで厳密確定し、OEIS 未登録を確認、
  Lean で $h\le4$ の表を `native_decide` 検証。→ RC のショート/ツール枠に十分。
- **成功（本線）**: $p_{\min}(T_h) - h$ の段差の onset を確定し、Královič の $\lg^*$ と整合／
  不整合を述べる。加えて木族 NS 反駁サイズの厳密表を副産物として提示。
- **撤退条件**: ①正規化の確認で Královič が既に手数も与えていた ②木 DP が組めず
  $h\le4$ で止まり数列が短すぎて何も言えない（3日試して駄目なら候補4へ資産を横流し）。

## 6. Lean 計画

- **L2（有界全数検査）**: `cbt_pmin_table : ∀ h ≤ 4, pmin (cbt h) = ...` を `native_decide`。
