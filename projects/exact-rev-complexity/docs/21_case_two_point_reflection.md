# 21 — 完走事例: 2点反射クエリゲームの厳密値（periodic-tm, 2026-07）

本リポジトリの勝ちパターン（厳密全数 → 二重実装照合 → 閉形式 →
Lean 二層検証 → 表の自動生成 → 執筆）を、ペブリング以外のトピックで
**最初から最後まで完走した事例**。方法論の移植可能性の実証として記録する。

## 対象の量

f を [N] 上の置換（f^ℓ = id、点 0 の軌道長 ℓ を約束）とし、オラクル
f への適応クエリで「軌道保存反射 ι₂ の 2 点 (0, 1) での値」を大域整合に
出力する最小最悪クエリ数 q(N, ℓ)。可逆計算との接続: ι₂ は
f = ι₁∘ι₂（2つの計算可能対合への分解、Nakano の involutory TM 基底）の
成分で、q はその評価コストの厳密値。

## 確定した厳密値（閉形式）

  **q(N, ℓ) = min( ℓ − 2, k₁\*(N, ℓ) )**（ℓ ≥ 3。ℓ = 2 は 0）
  k₁\* = min{ k : (k+1 以上の ℓ の最小約数) > N − ℓ }

- 漸近則は **ℓ − 2**。小 N 側は「別軌道シナリオの窒息」を巡る
  余剰点・約数算術が支配する（minDiv の閾値でジャンプ。
  例: ℓ=6 は N=11→12 で 3→4）。
- 表: periodic-tm `research/data/query_game_values.csv`
  （45 セル自動生成、42 セル厳密ソルバで検証、不一致 0、手編集禁止）。

## 本リポジトリの候補との関係

- 型としては (b)「計算されただけのものを証明する」の変種
  （自分で計算した数表 → 閉形式 → 証明・形式化）。
- `idea05`（reversible busy beaver）と同じく「敵対者・戦略」系の
  全数計算だが、こちらはゲーム木ミニマックスなので `revpebble.py`
  エンジンとは独立。ミニマックス＋正準化のコードは periodic-tm 側に
  あり、状態空間がゲーム木の候補（対話型・クエリ型の量）を将来
  扱うならそちらを種にできる。
- OEIS 照合は実施のうえ**不採用**（値列は minDiv 由来の階段関数で
  数列としての独立の面白さが薄い）。全段を機械的に踏むのではなく
  段ごとに採否を判断した記録として残す。
