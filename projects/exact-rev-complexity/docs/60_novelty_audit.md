## 3. ✅ **新規と判断**: 消去予算 $e$ の下での**最小手数**と飽和点 $e^*$

**判定: 新規。ただし主張を正確に絞る必要がある。**

一次確認の結果:

| 文献 | 消去（erasure）の扱い | 時間の最小化 |
|---|---|---|
| **Knill 1995** | **言及ゼロ**（"erasure"/"erase" の出現 **0 回**） | する（$F(n,S)$ が最小手数） |
| **Královič 2004** | **言及ゼロ**（出現 **0 回**） | 空間が主。時間は上下界 |
| **LTV 1998** | **m-erasure pebble game を定義**（我々の $e$ と同じ規則） | **しない**（Lemma 1 は特定構成の時間） |
| **BTV 2001** | 言及 2 箇所のみ（動機の説明） | する（時間空間トレードオフ） |

→ **「消去を予算パラメータにしたうえで手数を最小化する」設定は、
消去を持つ文献（LTV）は時間を最小化せず、時間を最小化する文献（Knill・Královič）は
消去を持たない、という形で空白になっている。** ここが本プロジェクトの本丸。

**したがって定理 A の主張はこう書く**:
> Knill の床 $2n-1$（Observation 2.2(i)、$S\ge n$ で達成）に、
> $p \ll n$ のペブルしか無い場合でも $e^*=\lceil (n-1)/(p-1)\rceil-1$ 回の不可逆消去で到達でき、
> かつ $e^*-1$ 回では到達できない。

この形なら既知部分（床の値）と新規部分（消去との交換率）が分離されていて安全。

## 4. ✅ **決着（2026-07-27、実測）: 定理 B1 の改良は成立。加法的に 1 ブロック**

### 4.0 実装が決着させた（解釈の議論は不要になった）

担当者が **LTV の Procedure A を我々のモデルで実装**し（`scripts/exp03_ltv.py`）、
生成した手順を**検証器に通した**（`data/exp03_ltv_compare.csv`、全 45 行で `ok=1`
＝規則・ピーク・消去回数・clean 終端をすべて満たす）。結果:

$$\mathrm{reach}_{\text{LTV-A}}(p,e) = (e+1)\,2^{p-2} \quad (e\ge1),
\qquad \mathrm{reach}_{\text{ours}}(p,e) = (e+2)\,2^{p-2}$$

**$p\in\{4,\dots,8\}\times e\in\{1,\dots,6\}$ の 30 点すべてで
実測値が $(e+1)2^{p-2}$ に一致**し、我々の式は常に真に大きい（比は $(e+2)/(e+1)$、
$e=1$ で 1.50、$e=6$ で 1.14）。

→ **素朴な換算が正しかった。改良は「同じピーク・同じ消去回数で 1 ブロック（$2^{p-2}$）多く進む」。**
$e=0$ では LTV-A もピーク $n+1$ で $2^{p-1}$ に達する（踏み台の消去が起きないため）ので、
**両者は $e=0$ で一致し、$e\ge1$ で我々が上回る。**

### 4.1 ⚠️ 私（統合担当）の論証には誤った仮定があった — 記録として残す

## 4bis. （旧記述・記録として保存）当初の懸念

**規約の不一致により、改良かどうかが未確定。担当者に実装での決着を依頼済み。**

LTV Lemma 1（本文 line 341）:
> There is a winning strategy with $n+2$ pebbles and $m-1$ erasures for pebble games $G$ with
> $T_G = m2^n$, for all $m\ge1$.

**問題は換算である**:
- LTV **line 316**: 「the pebble game of length $T_G = 2^n-1$ with $n$ pebbles」
  → LTV の規約は **$n$ ペブルで長さ $2^n-1$**（Královič $S^{-1}(p)=2^p-1$ と同じ）。
- 我々の規約は **$\mathrm{reach}(p)=2^{p-1}$**。両者は端条件ブリッジ $(2^p-1+1)/2=2^{p-1}$ で繋がる。
- さらに LTV **脚注1**: 「節点 0 の常設ペブルを数えるなら $n+1$ ペブル」→ **数え方に 1 のずれ**。

素朴に $p=n+2$, $e=m-1$ と置くと LTV は $(e+1)2^{p-2}$ を保証し、我々の $(e+2)2^{p-2}$ は
加法的に $2^{p-2}$ 改良になる。**しかしブリッジや脚注の数え方を採ると結論が変わりうる**
（最悪の場合 LTV が $(e+1)2^{p-1}$ を保証し、$e\ge1$ で**我々のほうが弱くなる**）。

**決着方法（依頼済み）**: LTV の Procedure A を我々のモデルで実装し、
検証器 `verify_schedule` に通して (ピーク, 消去回数, 到達長) を実測する。

## 8. ⚠️ 候補10 の射影ガベージ模型は「関係データベースの最小キー」と同一（2026-07-27、統合担当の確認）

担当者が自ら撤退条件として挙げた点（「$g_{\mathrm{proj}}$ が関係データベースの最小キーとして
既知と判明したら撤退」）を確認した。**同一である。**

### 8.1 対応

射影ガベージ模型 $g_{\mathrm{proj}}(f) = \min\{|S| : x \mapsto (f(x), x|_S)$ が単射$\}$ を
関係 $R = \{(x, f(x)) : x \in \{0,1\}^n\}$（属性 $X_1,\dots,X_n, Y$）として読むと:

> 「$x \mapsto (f(x), x|_S)$ が単射」 $\iff$ 「$S \cup \{Y\}$ が $R$ の**スーパーキー**」

したがって $g_{\mathrm{proj}}(f)$ は **$Y$ を含む最小スーパーキーの大きさ $-1$** であり、
DB 理論の**候補キー／最小キー**そのものである。

- **最小キーを求める問題は NP 困難**（**Lucchesi–Osborn, *Candidate Keys for Relations*,
  JCSS 1978**）。近年も研究が続いている（*Targeted Least Cardinality Candidate Key for
  Relational Databases*, **ICDT 2024**）。

### 8.2 影響: 「量の新規性」は主張できない。残るのは橋と厳密データ

- $g_{\mathrm{proj}}$ という**量そのものは既知の概念**（最小キー）。
  「$\mathrm{MAJ}_3$ が下界が緩む最小例」は、既知の量についての小さな組合せ的観察にとどまる。
- **ただし残るものはある**:
  1. **可逆回路としての解釈**（ガベージ線 = 通した入力線）と DB の最小キーを繋ぐ**橋**。
     この対応が明示的に書かれた文献は見つかっていない（要さらなる確認）。
  2. **入力が簡潔表現（ブール関数）で与えられる**点が DB 設定と違う。
     DB は関係インスタンスや FD 集合が入力で、こちらは $2^n$ 行を関数で圧縮して与える。
     計算量の議論が別物になる（担当者の表の (e) と同じ論点で、そちらは coNP 困難として既知）。
  3. 小さい $n$ の**厳密表**（$n=3$ の全 4140 集合分割、$n=4$ の 65536 関数）。
- **Lean 形式化の価値は残る**（`projOK_iff_subcube` 等）。ただし
  「新しい定理を形式化した」ではなく「既知の概念を可逆計算の言葉で形式化した」と書くべき。

### 8.3 判定

**候補10 は「新しい量を見つけた」路線では成立しない。**
`docs/idea10` §5 の撤退条件に照らすと**撤退が妥当**。ただし完全な撤退ではなく:

- **格下げして候補7（小ビット幅回路の最適値）に統合する**のが筋。
  Lean の `odd_perm_not_in_closure`（パリティ障害で線を 1 本増やす必要がある）は
  候補7 の下界側で使える資産である。
- あるいは**「可逆回路のガベージ = DB の最小キー」という橋を主題にする**（§8.2-1）。
  これは `docs/30_cross_field.md` の (M)/(Q) 基準で言えば **(Q) 問いの移送**にあたるが、
  **DB 側に我々のデータが答える未解決問題があるかは未確認**。先に確認すべき。
