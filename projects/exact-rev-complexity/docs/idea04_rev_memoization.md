# 候補4 — 可逆メモ化・可逆部分評価の厳密時空トレードオフ

> 一行: **自分の過去論文（rev_memoization, rev_PE）の漸近的主張を、厳密最適値で裏打ちする。**
> 期待値: 新規性 中／成功確率 **高**／既存資産 大（候補1と抱き合わせ推奨）

## 1. 厳密量の定義

メモ化の依存関係を DAG として取り出し、その上の厳密可逆ペブリング値を求める。

対象 DAG 族:
- **Fibonacci 型**: $F(n)$ の呼び出し DAG（頂点 $0..n$、$v$ の先行点 $\{v-1, v-2\}$）
- **二項係数型**: パスカルの三角形の DAG（$C(n,k)$ 依存）
- **編集距離型**: $m\times n$ グリッド DAG（各セルの先行点は左・上・左上）
- **区間 DP 型**: 行列連鎖乗算・最適 BST の $O(n^3)$ DP の依存 DAG

各々について $p_{\min}$、$M^*(G,p)$、トレードオフ曲線、最適スケジュールの構造。

**キラー比較**: 既存実装（`2017_rev_memoization` / `2021_rev_memoization2` / `rev_PE`）が
実際に使っているスケジュールを同じモデルで手数評価し、**厳密最適との差**を出す。
「我々の実装は $n\le N$ で最適、$n=K$ から $c$ 手だけ損をしている」と言えれば強い。

## 2. 既知と空白

> **探索前に必読**: この候補に効く既知事実は [`22_known_facts_ledger.md`](22_known_facts_ledger.md) の KF-01, KF-02, KF-05, KF-11, KF-19, KF-23。
> 新しい主張を立てたら、まずこれらに一致・包含されないか当てる（探索の負のフィルタ）。
> 台帳の「含意」欄がそのまま**書いてはいけないこと**である。

- **既知（自分の仕事）**: 可逆メモ化の設計と漸近評価、可逆部分評価の枠組み。
- **空白**: **最適性が未証明**。実装が最適スケジュールからどれだけ離れているかを
  誰も測っていない。DP の依存 DAG に対する厳密可逆ペブリング値の表も無い。
- **関連**: グリッド DAG の**標準**ペブリングは古典的に研究されているが（Cook のピラミッド下界等）、
  **可逆**版の厳密値は未整備。Královič の「標準ペブル × 鎖」合成上界と比較して
  「合成上界がどれだけ緩いか」を厳密に測れる ← これも新規の言明になる。
- **量子側の接続**: 量子アルゴリズムで古典 DP を可逆に走らせるときのアンシラ管理と直結
  （Meuli 等の SAT ベース手法と比較できる）。応用の動機として書ける。

## 3. 機械化の設計

`scripts/revpebble.py` に DAG 生成関数を足すだけ（**先に tests/ へ期待値**）。

```python
def fib_dag(n): ...      # 先行点 {v-1, v-2}、頂点 0,1 は free
def grid_dag(m, n): ...  # 先行点 左・上・左上、境界は free
def pascal_dag(n): ...
```

- 状態空間の壁: グリッド $4\times4$ = 16 頂点なら素朴 BFS で足りる。$6\times6$ 以上は
  **フロンティア DP**（対角線ごとの断面状態）に切り替える。グリッドは断面幅が小さいので
  この手が効く（候補1の木 DP と同じ発想）。
- Fibonacci 型は幅2の帯なので $n$ を大きく取れる → **数列が長く取れて閉形式推定に向く**。
  ここが最初の成果になりやすい。
- 既存実装のスケジュール抽出: インタプリタに trace を吐かせ、
  (put/take, 頂点) 列に正規化して手数を数える。差分は
  先行プロジェクトの `schedule_extract.py` の分類（部分消去の交錯・不均等セグメント・早期再配置）を流用。

## 4. 初日の実験

```bash
python3 scripts/exp04_memo_dags.py --fib-nmax 24 --grid-max 4 --pascal-nmax 6
```

初日の目標: **Fibonacci 型 DAG の $p_{\min}(n)$ と $M^*(n)$ の数列を $n\le24$ で出し、OEIS 照合。**
帯幅2なので $n$ を大きく取れ、初日で「数列 + 差分構造 + OEIS 未登録」まで到達できる。

### 進捗（2026-07-27）

`scripts/memo_dags.py`（`fib_dag`, `grid_dag`, `pascal_dag`）を実装し、
`tests/test_exp04_memo_dags.py` で構造テスト＋回帰値を固定した。目標の $n\le24$ を超え
Fibonacci 型は素朴 BFS で $n\le29$ まで到達（OEIS 未登録を確認）。グリッド型は
$k\times k$ を $k\le5$、パスカル型（中央二項係数目標）は $n\le6$ まで。
詳細・数表・次の一手は `data/exp04_results.md`。

### 続報（2026-07-27）— フロンティア DP は却下、双方向 BFS で $n\le33$, grid $k\le6$ へ拡張

`revpebble.py` の toggle 規則（取る操作にも先行点が必要）を確認すると、
**窓幅一定のフロンティア DP は最適解を捉えられない**（Bennett/Knill の
非局所的な二分再帰が必須になるため）。候補1（`docs/idea01_trees_dags.md` §3.2）も
独立に同じ結論に達している。代わりに **双方向 BFS（`scripts/frontierdp_memo.py`
`bidir_bfs`）** を実装した。toggle は対称操作なので状態遷移グラフが無向になり、
両端から探索して交差点で合流させれば**素朴 BFS と完全に同じ厳密値**が得られる
（近似ではない）。素朴 BFS が届く全域（fib $n\le21$, grid $k\le5$, pascal $n\le6$,
鎖 $n\le14$, 木・ピラミッド）で全 $p$ 一致を確認済み（`tests/test_exp04_frontier.py`）。

これにより Fibonacci 型は $n\le33$（$p_{\min}=10$ に到達）、grid は $k\le6$
（$p_{\min}=10, M^*=117$）まで拡張。$p_{\min}$ ブラケット長 $1,1,2,2,4,4,8,8$ が
**境界まで含めて確定**（$p_{\min}=9$ のブラケットが正確に長さ8で終わることを
$n=33$ で確認）。$L(10)=L(11)=16$ という次の予想はまだ未検証。詳細は
`data/exp04_results.md` §11。

### 続報3（2026-07-27）— ビットマスク化で $n\le48$、grid $k=7$（一部）へ拡張

`bidir_bfs` の状態表現を int ビットマスクに変更（候補1 `exp01b_engine.py` と
同じ発想、停止規則は §12 の証明のまま独自実装）。frozenset 版と全域で再一致確認
のうえ、fib(33) が287秒→10秒（約29倍）に高速化。fib $n\le49$、grid(7,7) は
$p_{\min}>11$ まで到達。

**$L(10)=16$ が確定**: $p_{\min}=10$ が $n=33..48$（16点連続）、$n=49$ で
$p_{\min}=11$（$M^*=231$）に切り替わることを、資源競合下で3回独立に再試行して
一致確認した。$L(11)=16$（$n=64$ 付近での再切り替え）はまだ未検証。
詳細 `data/exp04_results.md` §13。

grid(7,7) の $p_{\min}$ も確定（$p=12$、$M^*=195$。§13.5）。

### 続報4（2026-07-27）— CP-SAT interval・消去予算 $e$・実プログラム DAG

team-lead 提供の CP-SAT retention interval 定式化（`scripts/cpsat_interval.py`,
編集禁止）を fib/grid/pascal に適用し、既知値・候補3 の `landauer_bfs` と全点一致を
確認した（`tests/test_exp04_cpsat.py`, `.venv/bin/python` 必須）。ただし
**$e=0$ で $n$ が大きいと CP-SAT は解けない**（先行点が2個以上のため被覆制約が
鎖より難しい。$e=0$ 領域は bidir_bfs に任せる役割分担が判明）。

消去予算 $e$ を増やすと $M^*$ が floor $2N-1$ に飽和する点 $e^*$ を fib（5点）・
grid（4点）で測定。鎖の公式 $e^*=\lceil(n-1)/(p-1)\rceil-1$ の**約2倍**という
弱い観察があるが1点ずれがあり未確定（`data/exp04_results.md` §14.2）。

**新規**: `scripts/real_program_dags.py` に依存構造が異なる実プログラム DAG
（0/1 ナップサック=可変ジャンプ、行列連鎖乗算=区間長比例の高in-degree）を追加し、
bidir_bfs で厳密表を確定（mcm(7) まで、knapsack 複数ケース）。詳細 §14.3。

**未着手**: $L(11)=16$ の検証、$e^*$ の閉形式（点数不足）、実プログラム DAG の
拡大（mcm(8) 以上）、既存実装（`fib.janus` 等）との定量比較、Lean 二層検証。

## 5. 成功判定と撤退条件

- **成功（最小ライン）**: Fibonacci 型・グリッド型の厳密表と OEIS 未登録の確認、
  既存実装との差の定量化1件。
- **成功（本線）**: $M^*$ の漸化式（帯状 DAG の一般公式）+ 既存実装の最適性/非最適性の証明 +
  Královič 合成上界の緩さの厳密評価。
- **撤退条件**: グリッドで状態爆発してフロンティア DP も組めない場合は
  Fibonacci 型（帯幅2, 3）に絞って短報にする。撤退しても必ず何か出る安全な候補。
