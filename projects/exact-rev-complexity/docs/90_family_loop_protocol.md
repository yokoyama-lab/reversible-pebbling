# 無人ループの手順書（族アトラス）

**このファイルはこのループの唯一の指示書である。**
起動・引き継ぎ・トラック切り替えのプロンプトは **`docs/92_loop_prompts.md`**
にコピペできる形で置いてある（毎回書き直さないこと。書き直すと規律が緩む）。

止めるのは人。自己ペースで回る。設計は jones-agenda の
`docs/loop-protocol.md`（135 反復動いた実績のあるループ）と同じ形にしてある。
違うのは**合否の中身**だけ: あちらは `lake build`、こちらは**証書の再生**である。

## 1 反復でやること（この順に、これだけ）

1. `docs/91_family_queue.md` を読み、**`状態: todo` の一番上の単位**を取る。
   飛ばしてよいのは「先行する単位が `done` でない」ときだけ（その旨を書いて次へ）
2. その単位の「完了条件」を満たす変更を書く（テストファースト: 先に `tests/` へ期待値）
3. `tools/loopcheck.sh` を走らせる
4. **通った** → キューの状態を `done` にし、`git commit`（1 反復 1 commit。push はしない）
5. **通らない** → `git checkout -- . && git clean -fdq scripts tests data/families` で
   **全部捨てる**。キューにその単位の「詰まった理由」を 2〜3 行で書き（ここだけは残してよい）、
   commit する。**同じ単位を 2 回続けて落としたら `状態: blocked` にして次の単位へ進む**

   **唯一の例外**（2026-08-05, U6b で実際に起きたので明文化する）: 落ちたのが
   **数学的な主張ではなく、台帳の構成についての検査**（「下界の行が 1 つ以上ある」など）で、
   かつ**データが良くなったせいで前提が崩れた**場合に限り、その検査を直して再実行してよい。
   判定基準は「その assert は $M^*$ や $p_{\min}$ について何か言っているか？」——
   言っていないなら直してよい。言っているなら**捨てる**。
   直した場合は**キューと commit メッセージの両方に、何が落ちてなぜ直したかを書く**。
   これは「主張を弱めて通す」への抜け道にしてはならない。
6. 1 行だけ進捗を報告して次の反復へ

## 合否は「探索」ではなく「証書の再生」

`tools/loopcheck.sh` の終了コードだけ。中身は

```
tests/test_families.py → family_atlas.py --verify → tests/test_revpebble.py → tests/test_exp01b.py
```

で約 10 秒。**探索（`--build`）は合否に入れない。**
入れると台帳が伸びるほど合否が遅くなり、ループが止まるからである。

**全部盛りにしない理由は実測してある**: `pytest tests/` 全体は **269 件・34 分 37 秒**
（2026-08-05 実測、全て pass）。1 反復ごとに回せる長さではない。
全体は**トラックを閉じるときに 1 回**回す（そこで落ちたら、どの反復が原因かは
1 反復 1 commit なので二分探索で特定できる）。
探索は反復の中で 1 回走らせ、出た値は**スケジュール証書つき**で台帳に残る。
以後の反復はその証書を再生するだけでよい。

## 証書が担保する範囲（誇張しないこと）

| 主張 | 証書 | 検証 |
|---|---|---|
| $M^*(G,p) \le m$（上界） | 長さ $m$ の合法スケジュール | 再生するだけ（軽い） |
| $M^*(G,p) \ge m$（下界） | **無い**。全数 BFS が根拠 | 再探索（重い） |

したがって台帳の値は `docs/STATUS.md` でいう**層3（機械実験）**である。
CP-SAT の `OPTIMAL` や CaDiCaL の UNSAT が付いた行だけ、下界にも独立の根拠が付く。
**「証明した」と書かない。「全数探索で確定した」と書く。**

## 絶対にしてはならないこと

* **少数点の当てはめを結論にする**（`docs/00_overview.md` §2.1。既に 4 回崩壊している）。
  閉形式を思いついたら、その反復では**計算可能域の上限まで回してから**しか書かない
* `data/families/atlas.csv` を手で編集する（`family_atlas.py --build` が唯一の経路）
* 1 実装だけで出した値を台帳に載せる（`pebbleable <= 13` では素朴 BFS と照合される。
  超える場合は `methods` に `mask` だけが立つので、**その旨を findings に書く**）
* 打ち切りを黙って落とす。届かなかったセルは `status: timeout` として**行を残す**
* トーラスと円筒を混同する（トーラスは向きづけると巡回するので DAG にならない。
  `scripts/families.py` の但し書きを読むこと）
* 第三者 owner のリポジトリを触る（このリポは `tetsuo-jp` なので可）

## 失敗は成果である

「この族はこのサイズで届かなかった」「この予想はこの $h$ で崩れた」はキューに残す価値がある。
無理に通すより、届かなかった場所が記録されている方が次の判断に効く。
とくに**当てはめの崩壊**はこのプロジェクトの主要な知見であり、
`docs/00_overview.md` §2.1 の表に 1 行足す価値がある。
