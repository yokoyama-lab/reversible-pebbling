## 4. 主張（レターに書く 3 点）

1. **消去は 0、しかし何も残らないプログラムも 0。**
   111/111 本で `erasures = 0`（言語が禁じる）。一方**終端で全状態がゼロになるプログラムは 0/111**、
   書き込みのあった配列 189 本のうち **122 本（65%）は take を一度もしない**、
   終端で空になる配列は **25 本（13%）**。
   → 「可逆＝何も残さない」という素朴な期待はコーパスの 1 本にも当てはまらない。
2. **払っているものはスタックであり、その正体はグラフ／top-down 再帰である。**
   スタック使用 36/111。上位は topDownCutRod 310, avl_delete 79, floyd_warshall 67,
   avl_insert 65, kosaraju_scc 60, bellman_ford 54。
   bottom-up DP（edit_distance・lcs・knapsack）は**スタックを一切使わない**（裏面の確認）。
   スケーリングでは gcd_fib で `stack_peak = k`、bubble_sort で `= n(n−1)/2` が
   測定 6 点すべてで成立（層 3。一般式は主張しない）。
3. **clean を捨てることの利得と対価が即値になった。**
   fib_pairs (n=13): impl 7 手 < clean の床 2N−1 = 13 < M* = 19。
   edit_distance (n=5): 35 → 117 手（3.3 倍）と引き換えに peak 35 → 10（3.5 分の 1）。
   → 実装は clean 性を捨てることで**いかなる clean スケジュールよりも速い**。

**方法論上の副産物**（査読者に効く。§5 に 1 段落）:
基準線との照合が **impl peak < p_min** を検出し、cutrod の DAG 対応の誤り
（逐次累積 max を同時可用性として誤モデル化）を暴いた。
**基準線は最適性の尺度であると同時に、モデル対応の検証器である。**
