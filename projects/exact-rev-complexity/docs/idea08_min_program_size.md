# 候補8 — 極小可逆言語における「最小プログラムサイズ」表

> 一行: **可逆言語の各プログラムに対し、同じ関数を計算する最小サイズを全枚挙で決め、
> 逆プログラムのサイズ比の厳密最悪値を出す。**
> 期待値: 新規性 高／成功確率 中／言語設計論としても書ける

## 1. 厳密量の定義

極小可逆言語 $L$（R-CORE の最小核 / Janus の部分言語 / RFUN の部分言語）を固定する。

- 意味領域を有限に切る: 状態空間 $D$（例: $k$ ビットのレジスタ、$|D|=2^k$）。
  各プログラム $P$ は $D$ 上の**置換** $[\![P]\!] \in S_D$ を表す。
- $K_L(\pi) = \min\{|P| : [\![P]\!] = \pi\}$ （$|P|$ = 構文木サイズ or トークン数）
- **逆化コスト** $\rho_L = \max_P |\mathcal{I}(P)| / |P|$
  （$\mathcal{I}$ = 言語が備える構文的逆変換）
- **表現力の厳密境界**: $S_D$ のうち $L$ で表せる置換の割合、
  サイズ $s$ 以下で表せる置換の数 $N_L(s)$（= 言語の「情報効率」）

## 2. 既知と空白

> **探索前に必読**: この候補に効く既知事実は [`22_known_facts_ledger.md`](22_known_facts_ledger.md) の KF-19, KF-22。
> 新しい主張を立てたら、まずこれらに一致・包含されないか当てる（探索の負のフィルタ）。
> 台帳の「含意」欄がそのまま**書いてはいけないこと**である。

- **既知（定性的）**: 可逆言語では「逆プログラムが構文的に得られる」（Janus の逆変換、
  R-CORE の対称性、RFUN の逆化）。これは**定性的な主張**として広く述べられている。
- **空白**: **逆化のサイズ比の厳密最悪値が誰も測っていない。**
  「逆は同サイズで得られる」は本当か？ どの構文（ループの条件、非対称な代入、
  分岐の assertion）が逆化でサイズを増やすのか。**構文糖ごとの逆化コストの厳密表**は無い。
- **もう一つの空白**: $N_L(s)$（サイズ $s$ で到達できる置換数）は
  「可逆言語の記述効率」を測る量で、言語設計の比較指標になりうるが未整備。
  異なる可逆言語（Janus vs R-CORE vs RFUN）を**同じ尺度で厳密比較**できる。

## 3. 機械化の設計

1. **言語の切り出し**: まず $D$ を小さく（$k=3$ ビット、$|D|=8$、$S_D$ は $8!=40320$）。
   構文は「増減代入 / スワップ / 条件付き反転 / from-until ループ / 逐次合成」程度に絞る。
   **絞り方の設計判断が本候補の質を決める**（絞りすぎると自明、緩めると爆発）。
2. **サイズ順枚挙**: サイズ $s=1,2,3,\dots$ の全プログラムを生成し、
   意味（置換）を計算して**初出のものだけ記録** → $K_L$ の表が下から埋まる。
   意味の正規化で重複を潰す（同じ置換に写るプログラムは1つだけ残す）。
   これは Cayley グラフ BFS と同型なので候補7の実装と共通化できる。
3. **既存インタプリタの流用**: `rcore-python` / `PyJanus` / `rwhile-C-ocaml` を
   意味計算のオラクルにする（自作評価器と**二重実装照合**）。
4. **逆化コスト**: 各プログラムに構文的逆変換を適用してサイズを測り、比の最大を取る。
   ループ不変条件を要求する構文で比が悪化するはず ← **予想として先に書いておく。**

## 4. 初日の実験

```bash
python3 scripts/exp08_min_prog.py --bits 3 --smax 6
```

初日の目標: $k=3$、サイズ $\le 6$ で
1. サイズ別の到達置換数 $N_L(s)$ の数列（→ OEIS 照合）
2. 「サイズ $s$ で $S_8$ の全置換に到達するか」の判定（到達飽和点）
3. 逆化コスト比の最大値を1つ実測

## 5. 成功判定と撤退条件

- **成功（最小ライン）**: $N_L(s)$ の表 + 逆化コスト比の厳密最悪値 +
  「この構文が逆化を高くする」という具体例。
- **成功（本線）**: 複数の可逆言語を同じ尺度で比較した表 +
  「逆化コスト比 $\le c$」or「$\Omega(f(s))$ の下界例」の定理 + Lean で意味論と表の検証。
  **言語設計への提言**（どの構文糖を入れるべきか）まで書ければ PEPM/PPL の本論文になる。
- **撤退条件**: サイズ枚挙が爆発して $s\le5$ で止まり、飽和点に届かない場合。
  その場合は言語をさらに絞る（構文を2つ削る）か、$k=2$ に落として構文比較に主張を移す。

## 6. Lean 計画

- L1: 逆化変換の**正しさ**（$[\![\mathcal{I}(P)]\!] = [\![P]\!]^{-1}$）を Lean で証明。
  これは単独でも価値がある形式化成果（既存の紙の証明を機械検証する）。
- L2: $K_L$ の表を有界検査。
