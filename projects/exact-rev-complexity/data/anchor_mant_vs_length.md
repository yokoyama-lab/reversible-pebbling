# アンカー DP: 格子解像度（mant）と長さ（T0）はどちらが効くか

**2026-08-13 夜間。3 台で同コスト比較。**

## ⚠ 結論: **同じ計算時間なら「長さ」が勝つ**（記述と逆）

`~/dev/overleaf/2026_exact_reversible_pebbling/CLAUDE.md` には
「**格子解像度が長さより効く**（T=141000/mant10 は T=98500/mant11 に負ける）」とあるが、
**同コストで比べると逆**だった。

### <host>（各約 525 秒・同一機・同一バイナリ）

| T0 | mant | 格子 | c ≤ |
|---:|---:|---|---|
| 6000 | 13 | | 2.520507396 |
| 8500 | 12 | | 2.519638031 |
| 12000 | 11 | | 2.519023477 |
| 17000 | 10 | | 2.518615996 |
| **24000** | **9** | | **2.518443269** ← **最適** |
| 34000 | 8 | | 2.518517656 ← **悪化** |

**mant=9 に最適点がある。**13 → 9 まで単調に良くなり、8 で悪化する。
**mant=12 は明確に劣位**（2.519638 vs 最適 2.518443、差 1.2e-3）。

改善幅は縮小していく: 13→12 が 8.7e-4、12→11 が 6.2e-4、11→10 が 4.1e-4、
10→9 が 1.7e-4、9→8 が **−0.7e-4**（悪化）。

### oci（各約 164 秒）

| 4000 | 13 | 2.521933941 |
| 5600 | 12 | 2.520737776 |
| **8000** | **11** | **2.519816137** |

**2 つの規模で同じ向き。**

## なぜ記述と食い違うか（推測・未確認）

元の比較（T=141000/mant10 vs T=98500/mant11）は**同コストではない**。
mant11 は格子が 2 倍なので、T が 0.7 倍でも**コストは 1.4 倍**。
「より多く計算した方が勝った」だけかもしれない。

⚠ **これは推測。**元の比較の条件（実行時間・機械）を確かめていない。

## 実務上の含意

**現在 5 日走っている `anchor-m12`（T0=700000, mant=12）は mant が高すぎる可能性が高い。**
同じ計算量なら **mant=9〜10** の方が良い（この予算では差 1.2e-3）。

**傍証**: oci が **44 分**で `T0=32000, mant=11` → **c ≤ 2.517941** を出した。
5 日走っているジョブの 2.517157 との差は **7.8e-4 しかない**。
**曲線は極めて平坦**で、長時間の追加計算の見返りは小さい。
ただし上の比較は $T_0 \le 17000$ の範囲。**大きい $T_0$ で逆転しないかは検証中**
（oci: T0=16000〜45000、s3: T0=32000〜90000）。

## 再現

```bash
gcc -O2 -march=native -pthread -o m34 m34_anchor_par.c -lm
./m34 <T0> <mant> --report 100000000     # 最終行の c<= を読む
```
