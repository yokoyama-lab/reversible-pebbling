## 2. 読み取り

### 2.1 実装は「clean 最適より速く、床よりも速い」— dirty の対価が定量化できた

fib_pairs と grid 系では impl moves = 書きっぱなしの put のみで、
**clean の床 2N−1 より小さい**（fib n=13: 7 < 13 < 19）。
つまり実装は **clean 性を捨てることで、いかなる clean スケジュールよりも速い**。
その代償が peak = N（全セル保持）と終端ガベージであり、
「clean にするなら最低いくら払うか」が M* 列で初めて即値になった
（edit_distance n=5 なら 35 → 117 手、3.3 倍。空間は 35 → 10、3.5 分の 1）。

### 2.2 ⚠️ 基準線の照合が cutrod の DAG 対応の誤りを検出した（方法論上の収穫）

cutrod で **impl peak 10 < p_min 14** が出た。忠実なモデルならありえない
（p_min 未満では到達不能）。原因はモデル化の誤り:
完全履歴 DAG は「r[k] を置くとき r[0..k−1] が**同時に**必要」とするが、
実装は max を**逐次に累積**するので r[k−i] を**一つずつ**使って消費する。
同時可用性を要求するペブリングの前提が、この族の実装には当てはまらない。
→ cutrod 行の基準線は**無効として扱う**（表には残し、無効の理由を明記）。
**「基準線の照合は対応付けの検証器としても機能する」**——fib_pairs・grid・knapsack は
impl peak ≥ p_min で整合し、対応の妥当性が同じ照合で裏づけられた。

### 2.3 その他

- lcs と edit_distance は**同一の基準線**（同じ DAG）だが impl moves が違う（24 vs 35）。
  差は基底の書き込み（ed は境界に 1..n を書く、lcs の境界は 0 のまま）＋
  一致セルで値 0 が書かれない分。**モデルが同じでも実装の定数は違う**ことの実例。
- knapsack は cap=n+2 のため N が急伸し、基準線は n≤3 のみ。以降は正直に空欄。
