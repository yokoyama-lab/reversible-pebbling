# CP-SAT を輸入した結果（2026-07-27）— **正しいが、まだ BFS を超えていない**

実装 `scripts/cpsat_pebble.py`／テスト `tests/test_cpsat_pebble.py`（23 件 pass）。
`docs/30_cross_field.md` §1.5「ML 側の MILP/CP 技術を輸入する」の第一歩。

## 1. 定式化は正しい（BFS と全点一致）

時間展開したブールモデル（$x_{t,v}$ = 時刻 $t$ に $v$ がペブル済み、
毎ステップ高々1トグル、`put` は可用性を要求、可用でない `take` は $e$ を 1 消費）。

**検証**: BFS が届く範囲で**全点一致**を確認した。

| 対象 | 範囲 | 結果 |
|---|---|---|
| 鎖 $e=0$ | $n\le8$、$p=p_{\min}, p_{\min}+1$ | 全一致（`bfs`） |
| 鎖 $e\in\{0,1,2,3\}$ | $n\in\{4,6,8\}$ | 全一致（`landauer_bfs`） |
| 完全二分木 / ピラミッド | $h\le3$ | 全一致 |
| スケジュールの妥当性 | $n=6$ | 検証器で規則・ピーク・clean 終端を再検査 |
| 到達不能の判定 | $\mathrm{reach}(2)=2$ なので $n=3,p=2$ | `INFEASIBLE` を返す |

→ **定式化が真の最適解を落としていないことが確認できた**（これが使用の前提条件）。

## 2. しかしスケールしなかった（正直な否定的結果）

| 問題 | $n$ | 結果 |
|---|---|---|
| 最適化（$M^*$ を最小化） | 30, 50 | **UNKNOWN**（90 秒で時間切れ） |
| 決定問題（$2n-1$ 手で可能か） | 20 | ✅ $e=e^*-1$ で INFEASIBLE、$e=e^*$ で FEASIBLE（定理 A を確認） |
| 同 | 30, 50, 80 | **UNKNOWN**（120 秒で時間切れ） |

**BFS は $e$ 曲面を $n\le20$ まで出せているので、現時点で CP-SAT の利得はゼロ。**

決定問題に落とす（`feasible_in`: idle ステップを除き目的関数も外す）だけでは足りなかった。

## 3. 原因と次の一手

原因は**変数の個数**である。時間展開は $O(n\cdot T)$ 個のブール変数を要し、
$T\approx 2n$ なので $O(n^2)$。$n=50$ で 10,000 変数超になり、しかも
**時間軸方向の対称性**（同じ手順の順序入れ替え）が探索を膨らませる。

これは**先行研究が既に指摘している既知の壁**である。MOCCASIN（ICML 2023）は
Checkmate 等の先行 MILP が「各ノードの各使用ごとにブール変数を置くため $O(n^2)$ 変数になり
大きなグラフに載らない」と述べ、**retention interval**（各ノードの保持区間の開始・終了時刻を
整数変数にする）による $O(n)$ 変数の定式化に移った。

→ **次の一手: retention interval 型の定式化に書き換える。**
- 各頂点 $v$ について「何回置かれるか」の上限 $C_v$ を決め、$i$ 番目の保持区間の
  開始 $s_{v,i}$・終了 $t_{v,i}$（整数変数）と有効フラグ $a_{v,i}$ を持つ。
- ピーク制約は区間の重なり数 ≤ $p$（CP-SAT の `add_cumulative` が直接使える）。
- 可用性は先行点の区間が自分の開始時刻を覆うこと（`add_no_overlap` ではなく含意で書く）。
- 不可逆消去は「終了時刻に先行点の区間が覆っていない」区間の個数 ≤ $e$。

**この方向が本命。** `add_cumulative` はスケジューリング向けに強く最適化された伝播器なので、
ピーク制約が素朴な総和より格段に効くはず。

## 4. 教訓（`docs/00_overview.md` §2 に追記すべきもの）

- **道具を輸入するときは、その分野で「素朴な定式化は駄目だ」と分かっている点まで含めて輸入する。**
  今回は CP-SAT というソルバだけを輸入して、MOCCASIN が到達した**定式化の知見**を
  輸入し忘れた。ソルバより定式化のほうが効く。
- 一方で**素朴版を先に書いたことは無駄ではない**: BFS との全点一致で「モデルの意味は正しい」
  ことが固定できたので、interval 版を書いたときの検証台になる
  （素朴版 ⟷ interval 版 ⟷ BFS の三層照合ができる）。
